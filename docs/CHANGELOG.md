# Changelog

## 2.9.0

### 移除："只显示投屏画面"（fit）模式

独立浮窗已经能覆盖「桌面上只留画面」的场景，两套机制并存反而让窗口行为难以预测，因此整条链路删除：

- 菜单项「显示 → 只显示投屏画面」（⌘⇧T）与对应偏好开关
- `UserPreferences.fitWindowToMirror` / `transparentWindowBackground` 及默认值
- `MainViewController.fitWindowToMirrorIfNeeded()`、`savedMinSize`、`isRefittingWindow` 等贴合窗口状态
- `DevicePanelView.forcesBezelVisible` 与 `panelFrame(for:in:)` 的满窗分支

结果：主窗口恢复标准系统外观（标题栏、红绿灯、可自由缩放/全屏），画面永远按设备比例居中留边，不再走透明背景。

- `appcast.xml` 清理为 StageCast 空频道；`.gitignore`、`Secrets.swift.template`、release skill 全部改为 StageCast 命名。

- 项目目录更名为 `StageCast`，与 App 名称一致。

## 2.8.1

### 修复

- **窗口无法缩放**：`NSWindow.contentAspectRatio` 一旦被赋过值（哪怕是 `.zero`），AppKit 后续每次 resize 都会用 0 作除数算出 NaN 的宽高，`TransparentWindow` 的非有限几何守卫直接把这次 resize 拦掉，表现为「窗口完全拖不动」。删除所有 `contentAspectRatio = .zero` 赋值。
- **浮窗关闭崩溃**：`NSWindow` 默认 `isReleasedWhenClosed = true`，`close()` 会再发一次 release，与字典强引用冲突导致过度释放（`-[NSKVONotifying_NSWindow release]: message sent to deallocated instance`）。改为 `isReleasedWhenClosed = false`。
- **浮窗掉线**：窗口不再自动关闭，改为保留原位并显示「设备已断开 / 投屏已中断，窗口保留在原位」卡片，提供 **重新连接** 与 **关闭**。
- **重连失败**：`ScrcpyDeviceSource` 掉线后停在 `.error` 态，`connect()` 直接返回。新增 `resetForReconnect()`，并在 `AppState.startAndroidCapture(device:)` 复用已有源时先复位。
- **角标遮挡状态栏**：竖屏画面下移 54pt，避开通话/时间/电量。
- **圆角检测日志刷屏**：检测连续失败 6 帧后放弃，不再每帧重试。

## 2.3.0

### 新增：无线连接全面适配 Android 11+ 随机端口

Android 11 起「无线调试」不再使用固定 5555，而是随机 TLS 端口（实测 MIX 2S / Android 16 为 40513），
旧实现固定连 5555 必然失败。现在按分层回退依次尝试：

1. 输入显式端口（`IP:端口`）
2. 端口缓存（同一设备上次成功的端口）
3. USB 在场时读取设备 `service.adb.tls.port` / `service.adb.tcp.port`
4. 系统 mDNS（Network.framework）发现调试端口
5. 兜底 5555（旧设备 / 已执行 `adb tcpip`）

### 新增：IP 输入支持 `IP:端口`

输入框同时接受 `192.168.50.163` 与 `192.168.50.163:40513`，缺省端口走缓存或 5555。

### 新增：端口缓存

按设备记录上次成功端口（同时按 IP 与设备 GUID 存储），重连时优先复用；
连接失败自动重新发现（缓存不作为硬约束）。实测已写入 `wireless.portCache.ip.*` 与 `guid.*`。

### 新增：系统 Bonjour 发现（替代失效的 adb mDNS）

adb 自带的 Openscreen mDNS 在本机始终返回空列表（受 macOS 本地网络权限限制），
改用 Network.framework 的 NWBrowser 浏览：

- `_adb-tls-connect._tcp`：Android 11+ 调试端口
- `_adb-tls-pairing._tcp`：配对端口
- `_adb._tcp`：旧版无线 adb

要点：解析必须等到 `NWConnection` 的 `.ready` 才拿得到远端地址（在 `.preparing` 取消会永远解析不到）；
并强制 IPv4 解析，避免 Bonjour 返回链路本地 IPv6（`fe80::`）导致「有结果但解析不到地址」。

### 新增：配对后使用正确端口

配对成功后不再固定连 5555，改走分层流程；全部失败时提示用户填写手机显示的端口。

### 新增：多设备选择

发现多台设备时弹窗选择；单台直接回填。按「上次成功连接的 IP」优先排序，避免默认选错设备。

### 其他

- `Info.plist` 新增 `NSLocalNetworkUsageDescription` 与 `NSBonjourServices`，首次发现时请求本地网络权限
- 无线区高度预算补齐「扫描设备」「诊断」两行，底部说明不再被挤出

## 2.2.1

### 修复：多项「默认开启」被 registerDefaults 压制（关键）

`UserDefaults.register` 注册的值会穿透 `object(forKey:)`（进入 NSRegistrationDomain），
导致各 getter 的「未写入时用默认」分支永远不生效：

- `showDeviceBezel: false` → 外观还原（机型边框/圆角/侧键）依旧关闭，2.2.0 的恢复未生效
- `androidAudioEnabled: false` → 音频依旧关闭（实测 server 参数为 `audio=false`）
- `iosAudioEnabled: false` → 同上

统一改为 `true`，与各 getter 的默认语义对齐。实测 server 参数已变为 `audio=true`。

### 修复：圆角被启动黑帧误判为「直角屏」

投屏刚建立的前几帧是纯黑画面，四角对角线扫描全部无边界，
被误判为「直角屏」并在 3 帧确认后锁定，之后不再检测。

新增整帧均匀性校验：中心区与四角平均色全部接近时判定为「无有效内容」，
返回 nil 继续等待。实测 OnePlus 8 正确检出四角一致的真实圆角（median 90.5px）。

### 修复：无线连接区底部说明被挤出

`wirelessLayoutSize` 高度预算漏算「扫描设备」与「诊断按钮」两行，
底部说明文字被推出可视区。预算已与 `layoutWireless` 行序对齐。

## 2.2.0

### 修复：旧投屏无法退出（P0）

两个独立原因：

- **设备端进程未清理**：`adb shell` 被 terminate 后，设备上由 `app_process` 启动的 Java 进程已 detach，不会随之退出，继续占用 SurfaceFlinger 虚拟显示并向已关闭的 socket 推流。`stopCapture()` 新增 `pkill -f com.genymobile.scrcpy.Server`，失败时兜底 `killall`
- **child window 泄漏**：`captureInfoPanel` / `controlBarPanel` 被 `addChildWindow` 持有形成循环引用，`deinit` 永不执行。新增 `teardownChildWindows()`，在面板离开窗口层级时显式拆除。实测残留 4 个孤儿窗口 + 1 个控制条

### 修复：重启后圆角错乱（P0）

`detectedCornerRadiusInPixels` 面板侧缓存无任何重置点，新会话沿用旧半径。现在：
- 新会话开始时清空
- 分辨率变化时清空
- 首帧前用设备规格比例兜底渲染，避免圆角缺失跳变

### 恢复：外观还原默认开启（P1）

`showDeviceBezel` 默认值恢复 `true`。按机型渲染灵动岛/刘海/打孔/侧键与圆角的功能一直完整保留（`DeviceBezelView` 26KB + `DeviceModel` 77KB 机型库），此前只是默认关闭。
「只显示投屏画面」模式强制隐藏边框（窗口已收缩到画面尺寸，再画外壳会超出）。

### 改进：音频默认开启（P1）

- `androidAudioEnabled` 默认值改为 `true`
- **不做 Android 版本自动降级**：不擅自关闭用户设置，改为实际无音频数据流入时提示
- 音频设置变更时弹对话框，提供「立即重启 / 稍后」
- `ScrcpySocketAcceptor.audioEnabled` 从 `let` 改为可变，在 `start()` 前由最新配置同步，避免连接顺序判断错位导致控制通道失效

### 新增：音频不可用提示（P2）

启用音频但 6 秒内无音频数据流入时提示「该设备不支持音频投屏，scrcpy 音频通道需要 Android 11+」。

## 2.1.5

### 修复：竖屏上下黑边（根因）

`windowWillResize` 手写比例约束在 `fullSizeContentView` 下会误减 32pt 标题栏高度：

    windowH 556 → contentH = 556 - 32 = 524
    contentW = round(524 × 0.5) = 262   ← 实际绘制区高度仍是 556

导致窗口比例 0.4712 而视频 0.5，上下各留 16pt 黑边；且每次拖动边框都会重新算错，所以「长期存在」。

改用系统原生 `window.contentAspectRatio`，由 AppKit 自行处理标题栏与缩放边界，删除手写约束。

### 新增：像素级圆角检测

从解码后的 BGRA 像素判断画面真实圆角，实现「原始画面是直的就直的，带弧度就带弧度」。

- 沿对角线从四角向内扫描，在 d = r(√2−1) 处碰到圆弧边界，反推 r
- 四角投票取中位数；部分角测不到边界时（如底部导航栏与背景同色）按有效角计算
- 连续 3 帧一致才采纳，避免动态画面误判
- 检测失败自动回退 `DeviceModel.screenCornerRadiusRatio`

### 修复：圆角作用范围

圆角原先加在整个 renderView 上，有黑边时会切到黑边。改为只作用于 `videoDisplayRect`，圆角始终贴合视频边缘。

## 2.1.4

### 修复：「只显示投屏画面」上下残留白边/黑边

四个独立原因叠加，逐项修复：

- **Metal 黑边透明**：clearColor 的 alpha 为 0，视频比例与窗口比例存在 1~2pt 舍入误差时露出窗口底色。该模式下改为不透明黑边
- **窗口底色为白**：透明背景在部分窗口状态下仍会绘制系统底色。该模式下改用不透明黑，任何残余缝隙都不会显示白框
- **窗口沿用兜底比例**：纹理未就绪时用 9:19.5 估算，拿到真实分辨率后没有重新贴合，导致比例偏差。新增 onVideoSizeChanged 回调，视频尺寸就绪或横竖屏切换时自动重新贴合
- **标题栏高度误算**：contentLayoutRect 在 fullSizeContentView 下仍会减去 32pt 标题栏，导致窗口比视频高 32pt。改用 contentView.bounds 作为真实绘制区域

### 优化

- 面板在该模式下直接铺满区域，不再按 deviceAspectRatio 二次计算，避免比例不一致时露出底色
- setFrame 后以 contentView.bounds 实测校正，消除舍入误差

## 2.1.3

### 修复：鼠标滑动被识别为拖动窗口

根因是 `isMovableByWindowBackground` 与 `mouseDownCanMoveWindow` 未覆盖，AppKit 在派发 `mouseDown` 之前就把事件用于拖窗。

- `SingleDeviceRenderView` 新增 `mouseDownCanMoveWindow`：开启输入时返回 false，事件不再被窗口截走
- `DevicePanelView` 返回 false，`PreviewContainerView` 返回 true（容器空白处仍可拖窗）
- 新增 `⌥ + 拖拽` 移动窗口，投屏中也能调整窗口位置
- 清理废弃的 `transparentWindowBackground` 拖窗逻辑，统一由 `applyWindowMovability()` 控制：投屏中禁止背景拖窗

### 修复：调整画面时出现白边

- 新增 `windowWillResize` 等比约束：该模式下窗口只能按视频比例缩放，从根本上消除留白
- `TransparentWindow` 子类：缩放期间不绘制窗口背景，消除白边闪烁
- 该模式下关闭容器那圈 1pt 边框，并让窗口背景完全透明

### 新增：鼠标靠近时显示淡边框

窗口外框隐藏后，鼠标靠近边缘 12pt 内显示一圈 28% 白色淡边框，提示可缩放边界。

## 2.1.2

### 修复：只显示投屏画面

窗口此前始终保留 800×600 的最小尺寸与 24pt 内边距，导致画面外仍有大片留白。三处根因：

- `window.minSize = 800x600` 阻止窗口收缩到画面尺寸 → 进入该模式时临时降到 120×120，退出时恢复
- `calculatePanelFrame` 在非全屏时始终减去 `verticalPadding * 2` → 该模式下内边距归零
- `updatePreviewContainerFrame` 保留标题栏高度 → 该模式下偏移归零，并用 `fullSizeContentView` 消除顶部灰条
- 移除 `handleWindowResize` 中的二次 fit 调用，避免 setFrame 与系统 resize 相互触发形成死循环
- 窗口尺寸改为按「内容区」计算并扣除标题栏高度，比例贴合实际视频分辨率；横竖屏切换后自动重新贴合

## 2.1.1

### 修复：无线连接稳定性

- 实测发现 adb 在切换网络或空闲后会进入异常状态：手机 ping 通、端口可达，但 `adb connect` 报 `No route to host`。此时必须 `kill-server` + `start-server` 才能恢复
- 连接失败时自动重启 adb server 并重试一次
- 诊断流程在 `No route to host` 时自动插入「重启 adb → 重试连接」两步
- 设备列表监控检测到无线设备 `offline` 时自动重连（最多 3 次，先直接重连，失败再重启 adb）

### 修复：控制按钮定位

- 视频纹理未就绪时 `videoDisplayRect` 会退化成整个视图，导致按钮条贴到窗口底边而非画面底边。新增 `fallbackVideoAspect` 兜底，用已知分辨率推算画面矩形

## 2.1.0

### 新增：无线连接三方案

- **B 诊断面板**：连接时逐步显示 `kill-server` → `start-server` → `connect` → `devices` 的原始输出，失败原因一目了然
- **C 配对码连接**：支持 Android 11+ 无线调试配对（`adb pair`），填配对端口 + 6 位码即可，无需 USB
